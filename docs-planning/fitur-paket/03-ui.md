# Rencana Perubahan UI — Fitur Paket

Asumsi: [`01-database.md`](./01-database.md) & [`02-backend.md`](./02-backend.md) sudah jalan.

**Catatan penting**: redesain "Drawer Bertingkat" (`Progress redesain drawer.md`)
sudah **dibatalkan** — semua panel geser (`Sheet`) sudah dikembalikan tampil sebagai
modal terpusat (lihat `components/ui/sheet.tsx`, yang sekarang secara visual identik
dengan `dialog.tsx`). Komponen `Sheet*`/`SheetBreadcrumb`/dst. tetap dipakai apa
adanya di kode (nama & API-nya tidak diganti balik ke `Dialog*` supaya tidak
menyentuh ulang semua file yang sudah memakainya), cuma tampilannya modal, bukan
drawer. Rencana di bawah ini **mengikuti kondisi itu**: Paket ditambahkan sebagai
level list inline baru di dalam modal layer-1 (`SheetContent layer="1"`), persis
seperti Alokasi sekarang — bukan modal terpisah baru — supaya jumlah modal yang bisa
terbuka bersamaan tetap dibatasi 2 (layer-1 + layer-2), sama seperti sebelumnya.

## 1. `planning-detail-sheet.tsx` (UBAH)

Sekarang: Sheet layer-1 langsung menampilkan daftar **Alokasi per tahun** (expand
inline pakai `alokasi-expand-panel.tsx`).

Nanti: Sheet layer-1 menampilkan daftar **Paket** dulu (kartu/baris: nama paket, kode
paket, jenis F/NF, RO, badge skor kalau sudah ada). Klik satu Paket → expand inline
menampilkan `PaketExpandPanel` (BARU) yang isinya:

- Ringkasan field paket (jenis, masa pelaksanaan, komponen, wilayah sungai, tag FKB/FKW/MPA, indikator RENJA, catatan pembina/SSPSDA) — read-only + tombol "Edit Paket" yang membuka Sheet layer-2 (form).
- Di bawahnya, daftar **Alokasi per tahun milik paket ini** — pakai ulang `alokasi-expand-panel.tsx` yang sudah ada (cuma sumber datanya sekarang `paket.alokasi`, bukan `planning.alokasi`).

State `panelsWithSubDrawer`/`showAlokasiForm` yang sudah ada untuk efek "pushed" tetap dipakai, tinggal ditambah kondisi baru untuk "form Edit Paket sedang terbuka".

## 2. `components/planning/paket-expand-panel.tsx` (BARU)

Nyontek struktur `alokasi-expand-panel.tsx` (fetch by id, terima props `onNavigateToList`/`onSubDrawerOpenChange` yang sama). Isi: ringkasan field Paket + daftar Alokasi-nya (reuse `AlokasiExpandPanel` sebagai child, bukan ditulis ulang).

## 3. `components/planning/paket-form-dialog.tsx` (BARU)

Sheet layer-2 untuk create/edit satu Paket. Breadcrumb: `Daftar Planning › {proyek} › {Tambah/Edit} Paket`.

Field, urutan disarankan (kelompokkan supaya tidak jadi satu form raksasa — pakai `<Accordion>` yang sudah ada di `components/ui/accordion.tsx`, konsisten dengan pola "Riwayat Perubahan" di planning-detail-sheet):

1. **Identitas**: Nama Paket, Kode Paket (opsional), RO (cascading select: Program→Kegiatan→KRO→RO, reuse pola yang sudah ada di `planning-form-dialog.tsx` untuk KRO/RO kalau ada, tinggal ditambah 1 level Komponen di bawah RO), Komponen (select, muncul setelah RO dipilih), Jenis Paket (F/NF — radio/select), Masa Pelaksanaan (select, sama seperti yang sekarang ada di planning-form-dialog, cuma pindah lokasi).
2. **Kesesuaian & Wilayah Sungai**: Wilayah Sungai (select, sama komponen yang sudah ada di planning-form-dialog, pindah ke sini), Dokumen Lingkungan (status, text/select bebas dulu sesuai `dokLingStatus`).
3. **Indikator RENJA** (accordion collapsed by default — field banyak & jarang diisi semua): PN, PP, KP, PKPN, SP + Satuan ISP, SK + Satuan ISK, IRO + Satuan IRO, Tematik RENJA.
4. **Tagging**: checkbox FKB, FKW, MPA.
5. **Catatan**: Catatan Pembina, Catatan SSPSDA (textarea, seperti field catatan lain yang sudah ada).
6. **Skor**: read-only, tampil "Belum dinilai" kalau `null` — **tidak ada input manual** di form ini (skor dihitung sistem nanti, bukan diisi user).

Alokasi & Lokasi **tidak** diisi di form ini — tetap lewat alur yang sudah ada (`alokasi-form-dialog.tsx` dibuka dari dalam `PaketExpandPanel`, sama seperti sekarang dibuka dari `AlokasiExpandPanel`).

## 4. `planning-form-dialog.tsx` (UBAH)

- **Hapus** field Masa Pelaksanaan dan Wilayah Sungai (pindah ke `paket-form-dialog.tsx`).
- **Tambah** field baru: Sumber Usulan Proyek (select 5 opsi sesuai enum `SumberUsulanProyek`, dengan input teks tambahan yang muncul kalau pilih "Lainnya" — pola show/hide conditional field yang sama seperti field lain yang sudah pakai pola serupa di file ini kalau ada), Pola Rencana (text/select, tunggu konfirmasi keputusan terbuka #4 di overview sebelum implementasi final — sementara text bebas dulu), Kode Proyek (opsional, kemungkinan read-only/auto-generate — tunggu keputusan #5).
- Field Studi Kelayakan/DED/LARAP: **tidak perlu field baru** kalau UI kriteria dokumen yang sudah ada (kalau ada UI untuk `KriteriaDokumen`) sudah generic menerima `jenis` bebas — cukup pastikan 3 jenis ini bisa dipilih/diketik di situ. Kalau belum ada UI untuk KriteriaDokumen sama sekali, ini d luar cakupan dokumen ini (fitur existing, bukan bagian dari fitur Paket) — cek dulu sebelum menambah UI baru untuknya.

Setelah proyek dibuat/dibuka untuk edit, form ini **tidak lagi mengelola Paket langsung** — Paket dikelola dari `planning-detail-sheet.tsx` setelah planning tersimpan (planning harus punya id dulu sebelum bisa punya Paket, sama seperti Alokasi sekarang perlu planning id dulu — cek pola `create` vs `edit mode` yang sudah ada di file ini untuk konsistensi: kalau alokasi sekarang bisa diisi sekaligus saat create planning baru [nested], maka Paket harusnya juga bisa; ikuti pola yang sudah ada, jangan bikin UX beda untuk hal yang setara).

## 5. `app/(dashboard)/plannings/page.tsx` (UBAH)

- List planning yang di-grup per Kegiatan sekarang butuh source RO dari `planning.paket[].ro`, bukan `planning.alokasi[].ro` — sesuaikan grouping key.
- Total realisasi / progress bar per baris: jumlah dari semua `paket[].alokasi[]`, bukan `alokasi[]` langsung. Kalau kalkulasinya sudah didapat dari backend (include sudah dijumlahkan di sana per 02-backend.md), frontend tinggal pakai field itu — jangan hitung ulang di 2 tempat.
- Pertimbangkan tambah kolom/badge "Jumlah Paket" per baris planning (opsional, murah untuk ditambah karena datanya sudah ada dari include).

## 6. `app/(dashboard)/review/page.tsx` (UBAH, minor)

Sama seperti Fase 2 redesain drawer — ikut pakai `PlanningDetailSheet` yang sudah diupdate, otomatis dapat tampilan Paket tanpa perubahan tambahan di file ini, kecuali kalau ada logic lokal yang baca `planning.alokasi` langsung di sini juga (perlu dicek saat implementasi).

## 7. Master data — tab Komponen (BARU)

`components/master/` — tambah `komponen-tab.tsx`, nyontek `nomenklatur-tab.tsx` (yang sudah handle Program/Kegiatan/KRO/RO) tinggal ditambah 1 level. Daftar tab di `master-table.tsx` ditambah satu entri "Komponen".

## 8. Ranking / sort berdasarkan skor (BARU, kecil)

Di halaman/list yang menampilkan Paket (list inline di `planning-detail-sheet.tsx`, dan opsional list global kalau nanti dibutuhkan halaman "Semua Paket" lintas proyek — **belum diminta, jangan dibangun sekarang**, YAGNI): tambahkan sort by "Skor" (desc) sebagai salah satu opsi urutan, dengan skor `null` selalu di bawah. Ini murni UI sort, tidak butuh komponen baru — cukup opsi tambahan di sort control yang sudah ada (atau default sort kalau daftar Paket memang belum ada kontrol sort, tambahkan yang paling sederhana: `Array.prototype.sort` di frontend, bukan bikin endpoint sort baru dulu selama datanya sedikit per proyek).

## 9. Import Excel dialog (`components/import/import-excel-dialog.tsx`) (UBAH)

Preview/summary hasil parse (kalau ada tampilan preview sebelum commit import) perlu menampilkan struktur 2 level (Proyek → Paket), bukan flat, supaya user bisa cek grouping-nya benar sebelum submit. Detail UI-nya menyesuaikan komponen preview yang sudah ada sekarang — cek dulu bentuknya sebelum redesain.

## 10. Yang TIDAK berubah

- `lokasi-form-dialog.tsx`, `lokasi-detail-dialog.tsx`, `map-picker.tsx`, `cascading-wilayah.tsx`, `location-search-box.tsx` — semua tetap dipanggil dari alur Alokasi yang sama persis, cuma induknya (Paket, bukan Planning langsung) berubah, bukan cara kerjanya.
- `login/page.tsx`, `dashboard/page.tsx`, `users/*`, `sidebar.tsx`, semua komponen `ui/*` dasar (kecuali dipakai apa adanya oleh komponen baru di atas).
- Aturan permission (`canEdit`, `canSubmit`, `canReview`, `canManageAlokasi`, `canDelete`) — Paket mewarisi permission dari Planning induknya, tidak butuh permission baru kecuali diminta belakangan.
